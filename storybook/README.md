# Cosmos Storybook

Foundations, token tables and the React components for the Cosmos design system.

```bash
(cd .. && npm run build:tokens)   # the stories read ../dist/web/tokens.css
npm install
npm run storybook                 # http://localhost:6006
npm run build-storybook           # static build in storybook-static/
```

## How data gets here

- **Styling:** `.storybook/preview.tsx` imports `../dist/web/tokens.css`, so every page and component is drawn with the generated tokens.
- **Token data:** `npm run tokens` (run automatically before `storybook` and `build-storybook`) runs `../docs-site/scripts/generate-tokens.mjs`. The doc blocks read its output, `../docs-site/data/tokens.json`, through `src/blocks/data.ts`.
- **Fonts:** Lato 400, 700 and 900 load from Google Fonts in `.storybook/manager-head.html` (the Storybook UI) and `.storybook/preview-head.html` (docs pages and stories). `.storybook/theme.ts` sets Lato as the font for both.

## Icons

`src/components/Icon/paths.ts` holds the glyph paths exported from the Figma **Icons** page (`Icon / *`, 24 × 24, one filled path each). `<Icon>` draws them in `currentColor`, so each component colours its glyphs with its own icon tokens. Re-export a glyph from Figma rather than editing a path by hand, and keep it to the glyphs on the Figma Icons page (all 38 are in).

## Figma Code Connect

Code Connect shows the React snippet for a selected component in Figma Dev Mode. Templates are `.figma.ts` files next to the component they describe, and `figma.config.json` picks them up. Every Storybook component is connected, and so is every `Icon / *` glyph.

How the templates map Figma to code:

- **Defaults are left out.** A snippet only shows the props that differ from the component defaults, so a plain Primary Button is just `<Button label="Book now" />`.
- **State is design-only except Disabled.** Hover, Pressed, Focus and Open are browser states, so only `State=Disabled` reaches code (`disabled` or `isDisabled`). The Slider's `Pressed grow` state becomes `pressStyle="grow"`.
- **Selection becomes the starting value.** Checked, Selected and On become `defaultChecked` or `defaultSelected`, so the snippet renders the same picture without wiring state.
- **Icons come from the icon templates.** Each `Icon / *` template reports its code name, which the templates for Button, Chip, Tabs, Menu, List and the rest read from swapped or nested icons.
- **Parts report to their parent.** A tab, a segment, a list row, a menu row and the list leading and trailing parts each have their own template. Selected alone, they show the entry they become (an item object, or a `leading` or `trailing` prop). Inside a Segmented control, List or Menu panel, the parent builds its snippet from them, including rows added to the More rows or More items slot.
- **Placeholders are marked as such.** Things Figma cannot know, such as an image source, a radio group name, a click handler or an `aria-label` for a control with no visible label, appear as obvious placeholders (`"/path/to/image.jpg"`, `"group-name"`, `() => {}`, `"Describe the setting"`).

| File | Connects |
|------|----------|
| `src/components/<Name>/<Name>.figma.ts` | Badge, Button, Checkbox, Chip, Chip / Vertical, Input (which shows `PhoneInput` when Show Country is on), Radio, Slider, Snackbar, Switch and Tooltip |
| `src/components/Tabs/Tab*.figma.ts` | Tab / Primary and Tab / Secondary, as entries in the `items` of `<Tabs>` |
| `src/components/SegmentedControl/*.figma.ts` | Segmented control and its Segment |
| `src/components/List/List.figma.ts`, `List/code-connect/*.figma.ts` | List, List / Item, List / Leading, List / Trailing and List / Section header |
| `src/components/Menu/Menu*.figma.ts`, `Menu/code-connect/*.figma.ts` | Menu / Comfortable and Menu / Compact, and Menu / Item, Section header and Divider |
| `src/components/Icon/code-connect/*.figma.ts` | Each `Icon / *` component that `paths.ts` can draw. Generated by `npm run connect:icons` |
| `src/code-connect/helpers.ts` | Shared helpers the templates import: attribute formatting, literals and icon lookups |

Internal parts that only appear inside another component (Chip / Image, Chip / Remove, Snackbar / Control, Tooltip / Control, Slider / Thumb, Input / Country and the `Flag / *` components) are not connected; their parent's template covers them. After adding glyphs to `paths.ts`, run `npm run connect:icons`, then publish.

```bash
export FIGMA_ACCESS_TOKEN=...   # personal access token with Code Connect write scope, or put it in .env
npm run connect:publish         # uploads every template to Figma
npx figma connect parse         # checks the templates offline, no token needed
```

The snippets import from `@mmt/cosmos`, which is a placeholder until the components ship as a package.

## Component rules

- Each Figma variant axis is a prop with the same values, and Figma boolean properties are boolean props.
- Every visual value is a `var(--…)` from `dist/web/tokens.css`, using the component tier where one exists. `storybook/component-raw-value` rejects hex colours and px, rem or em lengths in component CSS.
- Text in a fixed-height box must land where Figma draws it. Browsers round Lato's ascent and descent to whole pixels, which draws 12 px text half a pixel high and 14 px text half a pixel low (16 px matches). Shift such labels by half a pixel (`calc(var(--space-3xs) / 4)` down for 12 px, `/ -4` up for 14 px), then compare the glyph bounds with Figma (`absoluteRenderBounds` on the Figma text node).
- Stories: one per variant axis, a kitchen-sink matrix that mirrors the Figma showcase frame with placeholder copy, and an examples story with realistic copy. Options under test get their own story marked "Under test".
- The MDX page summarises `../components/<name>.md` (Overview, API and screen-reader behaviour) and links to it.
