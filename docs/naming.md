# Cosmos token naming grammar

This is the contract. Every semantic token name is generated by the grammar
below, and `scripts/lint-tokens.mjs` fails the build on any name that is not.

The point of a grammar — rather than a list — is that a name can be **derived**
from intent instead of recalled. If you can describe what you need, you can
construct the name, and it will exist.

---

## 1. Color

```
<name> ::= <role> <modifier>* <on-context>? <state>?
```

Segments are joined with `-` and must appear in exactly this order.

| Slot | Values | Required |
|---|---|---|
| **role** | `bg` · `bg-surface` · `bg-fill` · `text` · `border` · `icon` | yes |
| **modifier** | emphasis: `primary` · `secondary` · `tertiary` · `disabled` · `inverse`<br>intent: `brand` · `link` · `focus` · `info` · `success` · `caution` · `warning` · `danger`<br>prominence: `strong` · `subtle` | no |
| **on-context** | `on-bg-fill` optionally followed by `strong` / `subtle` | no |
| **state** | `hover` · `active` · `selected` | no |

### Roles

| Role | Means | Example |
|---|---|---|
| `bg` | The page itself — the lowest layer | `bg` |
| `bg-surface` | A container sitting on the page: card, panel, section | `bg-surface-info` |
| `bg-fill` | An interactive or emphasis fill: button, badge, chip, toggle | `bg-fill-brand` |
| `text` | Foreground text | `text-secondary` |
| `border` | Strokes, dividers, focus rings | `border-brand` |
| `icon` | Icon fills, separate from text so icon weight tunes independently | `icon-success` |

### Intents

| Intent | Hue | Use for |
|---|---|---|
| *(omitted)* | neutral | Default, non-semantic UI |
| `brand` | brand blue | Primary actions and brand emphasis |
| `link` | brand blue | Clickable text |
| `focus` | brand blue | Keyboard focus indication |
| `info` | blue | Neutral information |
| `success` | green | Confirmation, completion |
| `caution` | **yellow** | Advisory — "fares may change" |
| `warning` | **red** | **Deprecated.** Use `danger`. |
| `danger` | red | Errors and destructive actions |

> `warning` resolves to **red**, not amber. This inverts the common convention,
> which is why it is deprecated in favour of `danger`. `warning` is reserved so
> it can return as the amber intent in a future major version without silently
> changing a live token's value. Until then, amber is `caution`.

## 2. The four rules

**R1 — Fixed order.** `bg-fill-brand-subtle-hover`, never
`bg-fill-hover-brand-subtle`.

**R2 — Only defaults are omitted.** The neutral intent and the resting state are
droppable; nothing else is. `bg-fill` is the neutral resting fill;
`bg-fill-brand-hover` spells out both.

**R3 — Grammatical implies existent.** If a name parses against this grammar and
sits inside the declared domain, the token exists. Two constraints keep that
promise affordable, and both are enforced by the linter:

- `bg-surface` takes an intent but **not** a prominence. A tinted container has
  one weight; if you need a strong tint, you want a fill.
- States exist on interactive roles only — no `text-secondary-hover`.

**R4 — Pairings are derivable, not remembered.** The foreground for any fill is
obtained by moving the prominence after `on-bg-fill`:

```
bg-fill-info-strong   →  text-info-on-bg-fill-strong   /  icon-info-on-bg-fill-strong
bg-fill-brand         →  text-brand-on-bg-fill         /  icon-brand-on-bg-fill
```

Neutral fills (`bg-fill`, `bg-fill-secondary`, `bg-fill-disabled`) take the plain
`text-*` scale. Every pairing is also stated explicitly in `pairsWith` in
`dist/tokens.json`, so it never has to be computed at all.

## 3. Non-color tokens

| Family | Pattern | Example |
|---|---|---|
| Typography | `<role>-<size>-<weight>` | `body-medium-bold` |
| Spacing | `space-<size>` | `space-md` |
| Radius | `radius-<size>` | `radius-lg` |
| Icon size | `icon-<size>` | `icon-md` |
| Border width | `border-width-<weight>` | `border-width-thin` |
| Focus ring | `focus-ring-<property>` | `focus-ring-width` |
| Motion | `motion-<property>-<name>` | `motion-duration-fast` |

Typography roles are `headline` · `title` · `body` · `label`; sizes are
`small` · `medium` · `large`; weights are `regular` · `bold` · `black`.
Composites expand to one variable per property, so the CSS name is
`--body-medium-bold-font-size`.

T-shirt sizes run `none` · `3xs` · `2xs` · `xs` · `sm` · `md` · `lg` · `xl` ·
`2xl` … `7xl` · `full`. `md` is the default in every scale — start there.

## 4. Primitive naming

Primitives are named for their **value**, deliberately, so that a hue or pixel
name in product code is self-evidently wrong:

```
color-<palette>-<step>      spacing-<px>       font-size-<px>
stroke-width-<px>           duration-<ms>      easing-<curve>
```

Primitive and semantic tokens share one flat output namespace, so the name alone
does not tell you the tier. `tier` in `dist/tokens.json` does, and the linter
enforces the rule that product code uses `semantic` only.

---

## 5. Adding a token

1. Add the raw value to `primitives` if it is not already there.
2. Add the semantic token as a `{reference}` — never a literal value.
3. Name it with the grammar above. If it will not fit, the taxonomy is wrong;
   extend the taxonomy rather than bending a name around it.
4. Write a `description` saying what it is **for** and what it is **not** for.
5. Add `$extensions.mmt` with at least `tier` and `status`; add `pairsWith` for
   a fill, `states` for an interactive token, `contrast` for a foreground.
6. Run `npm run build:tokens`. The linter checks all of the above.
